## 3. 合并结论速查

- **aliso 值得学**：搜索过程可视化、网盘计数、排序、同名变体、二维码交付、发现入口。
- **本站不能丢**：直链、有效性三态、本地索引/收割、百度加速、豆瓣、统计、工程细节。
- **第一批做**：状态条/耗时、网盘计数、多选+URL、排序、变体编号、移动端修复、二维码；公告/法律页并行。
- **不要做**：扫码-only、一次性渲染全部、公开他人原始搜索词、整体复刻后台、默认开启转存、无运营的需求板。
- **三个未解决**：aliso 历史范围、失效隐藏图标、“5 分钟后删除”文案。

## 4. 维护规则

1. **09 是现行事实来源；11 是 1:1 项目总纲**。aliso 的事实/证据变化先改 09；项目范围/排期/架构变化先改 11；不要把新结论只写进 01~07。
2. **01~07 冻结为证据附件**。除非发现事实错误且 09 已更新，否则不改原文；需要修正时在 08 记录“原表述/修正/原因”。
3. **08 是合并快照**。新增争议或新证据时，在 08 增加一行冲突/复核记录，不覆盖历史结论。
4. **10 是执行清单**。任务完成后更新状态、验收结果、回滚验证；计划与实现不一致时，回写 09/10 并注明原因。
5. **所有 aliso 结论必须可追溯**：页面 URL、公开脚本文件名、公开 GET 路径；推断必须标“推断/未验证”。
6. **所有本站现状必须可追溯**：仓库文件路径 + 行号（或函数/路由名）；无法确认的标“未验证”。
7. **不复制 aliso 的代码/样式/文案/图片**；不调用 aliso 接口；数据源使用本站自己的后端。
8. **不在文档中复述密钥值**。`ACCEL_TOKEN` 只写位置和风险，不写具体值。

## 5. 已知限制

- aliso 是持续更新的站点；01~07 的脚本文件名、结果数量、类型数量是 2026-10-19 的快照。
- 本次合并**没有重新访问 aliso.vip**，所有 aliso 结论来自 04 与 01~07 的记录。
- 管理后台未登录、未访问；路由/接口名只作范围证据，不构成复现指南。
- 本站 `frontend/dist` 是构建产物；发版前必须以 `frontend/src` 重新构建。
- `ACCEL_TOKEN` 硬编码风险仍未处理；公开部署前必须改为环境变量并轮换。
