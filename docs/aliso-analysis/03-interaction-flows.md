# aliso.vip 核心交互流程

- 分析日期：2026-10-19
- 说明：流程来自公开页面操作、公开打包脚本阅读和公开只读接口观察；标注“未验证”的环节未实际触发
- 合规：未登录、未提交需求、未调用管理接口；搜索仅使用公开页面自身触发的公开搜索请求

## 1. 首页加载与首屏

### 1.1 加载流程

```text
打开 https://aliso.vip/
  -> 返回 SPA 外壳（title/meta/OG/统计脚本）
  -> 加载 Vite 入口 index-BjJvZwZ3.js
  -> 懒加载 Home-Bv-pxTTG.js
  -> 并行请求：
       GET /api/public/settings
       GET /api/public/netdisk-configs
       GET /api/enabled-check-services
       GET /api/hot-search-words?_=<timestamp>
       GET /api/search-history
       GET /api/resource-titles
       GET /api/notice
  -> 渲染：Logo、H1、公告、搜索框、热门/历史/本地三行跑马灯、广告位、页脚
```

证据：首页公开页面；`Home.js` 中的初始化请求；公开只读接口响应。

### 1.2 公告弹窗

- 条件：站点配置了首页公告。
- 行为：首次进入时弹出公告浮层；点击遮罩或 × 关闭。
- 已读记录：`sessionStorage` 键 `alipansou_home_notice_seen_<siteName>`。
- 边界：同一会话内不重复弹出；换站点名后键不同。
- 证据：`Home.js` 中的 `home-notice-overlay` / `sessionStorage` 逻辑。
- 置信度：高（脚本观察），未逐次验证弹窗触发。

### 1.3 主题切换

```text
初始：localStorage.alipansou_theme_mode（缺省 light）
  -> 根节点 class = theme-light / theme-dark
点击 .theme-toggle
  -> 切换 light/dark
  -> 写入 localStorage.alipansou_theme_mode
  -> aria-label 在“切换到夜间模式”/“切换到日间模式”之间切换
```

实测：
- 点击前：`mode=dark`、`rootClass=home-page theme-dark`、aria=`切换到日间模式`
- 点击后：`mode=light`、`rootClass=home-page theme-light`、aria=`切换到夜间模式`
- 证据：2026-10-19 实际点击观察。

## 2. 搜索主流程

### 2.1 触发搜索

```text
输入关键词
  -> 点击搜索按钮（放大镜）或使用页面提供的搜索触发方式
  -> 去除首尾空格
  -> 空关键词：不发起搜索
  -> 屏蔽词检查：
       命中 blockKeywords -> alert("搜索关键词包含屏蔽词...") -> 结束
  -> router.replace({ path: "/search", query: { ai: 关键词 } })
  -> 保存搜索历史（前端调用历史接口）
  -> 获取搜索令牌 GET /api/search-token
  -> POST /api/stream-search
       headers: Content-Type: application/json
                X-Search-Token: <token>（如获取成功）
       body: { "kw": "<关键词>", "src": "all" }
  -> 流式读取响应，按行解析，持续追加结果
```

说明：
- 本次自动化中，直接输入 + 回车和点击放大镜图标的可点击性检查未稳定触发；通过直接访问 `/search?ai=<关键词>` 可复现结果页。因此“按钮/回车的具体绑定”标记为部分未验证。
- 搜索路由、请求体、令牌头、流式读取逻辑均可从公开脚本确认。
- 证据：`Home.js`；实际访问 `/search?ai=庆余年`。

### 2.2 流式结果与状态条

```text
开始搜索
  -> 状态条：当前显示 0、网盘类型 0、用时计时中
  -> 每收到一批结果：
       更新结果列表
       更新当前显示数量
       更新网盘类型数量
       更新各网盘计数
  -> 搜索未结束：显示“持续搜索中……”
  -> 用户点击取消：
       AbortController.abort()
       -> 状态条显示“搜索已取消”
       -> 已收到的结果保留
  -> 搜索结束：
       停止计时
       显示最终数量/类型数/用时
```

实测结果页示例：
- 当前显示：581
- 网盘类型：10
- 用时：8.1s
- 状态：持续搜索中……
- 网盘计数：夸克 283、百度 102、阿里 157、迅雷 12、123 11、天翼 5、115 5、光鸭 3、UC 2、移动 1
- 证据：2026-10-19 实际访问 `/search?ai=庆余年`（结果会随时间和数据源变化）。

### 2.3 流式失败回退

```text
POST /api/stream-search
  -> 请求失败 / 无有效结果
  -> 回退 POST /api/search
       headers/body 同上
  -> 解析响应并更新结果
```

- 证据：`Home.js` 中的 `ys()` 回退函数和 `/api/search` 调用。
- 置信度：高（脚本），未人为制造失败验证。

### 2.4 结果分组

```text
原始结果
  -> 解析为资源条目
  -> 按标题/规范化标题分组
  -> 每组：
       primary：主链接
       alternates：同名其他链接
       is_valid：有效性状态
       items：同组链接列表
  -> 渲染：
       单链接组 -> result-item
       多链接组 -> result-item + “同名更多结果”编号
```

- 证据：`Home.js` 中 `Ro`/`Po` 解析与分组、`result-block`/`resource-group-item` 模板。
- 置信度：高（脚本 + 页面渲染）；具体分组键的规范化规则未完全展开。

### 2.5 筛选

```text
默认：全部
点击网盘 chip
  -> 设置当前 disk_type
  -> 仅保留该网盘类型的结果
  -> chip 高亮
再次点击/选择“全部”
  -> 清除筛选
```

- 计数：每个 chip 的数量来自当前结果集的聚合。
- 移动端：横向滚动，带“左右滑动可切换网盘类型”提示。
- 证据：实际页面、`Home.js` 中的 `filter-btn`/计数计算。
- 注意：本次观察到的实现是单选；本站可在后端支持多选的基础上做得更好。

### 2.6 排序

```text
下拉选择：
  默认排序 -> 保持原始顺序
  按时间排序 -> 按 time 降序
  按名称排序 -> 按名称排序
```

- 实现方式：前端对当前结果集排序（脚本中为计算属性）。
- 证据：`Home.js` 中 `sort-select` 与排序计算。
- 置信度：高（脚本 + 页面）。

### 2.7 空结果与取消

```text
搜索结束且结果为空
  -> 展示提示图（如配置）
  -> 文案：“未找到相关资源，请尝试其他关键词”
  -> 若有关键词：显示“登记资源需求”按钮
       -> /demand
搜索被取消且无结果
  -> “搜索已取消，暂未收到资源结果”
```

- 证据：`Home.js` 空态模板；脚本中的 `unrelatedKeywords` 配置。
- 置信度：高（脚本），未实际构造空结果。

## 3. 资源获取弹窗

### 3.1 打开

```text
点击结果卡片 / “获取资源”按钮
  -> 按网盘类型上报点击（POST /api/public/netdisk-click）
  -> 设置弹窗数据：title、link、code、disk_type
  -> 打开 dialog-overlay
  -> 加载态：随机文案 + 旋转指示器
  -> 若百度：读取网盘配置中的 share_password
  -> 若网盘启用转存：请求转存接口，成功后替换 link/code
  -> 生成二维码（根据 link + code）
  -> 渲染弹窗内容
```

- 证据：`Home.js` 中 `ft()`、`ls()`、`yn()`、`dialog-overlay` 模板；公开接口 `/api/public/netdisk-configs` 中的 `enable_transfer`/`share_password` 字段。
- 置信度：高（脚本）；转存分支未实际触发。

### 3.2 弹窗内容

```text
二维码区
  ├── “请使用 <网盘> App 扫码获取”
  ├── “打开 <网盘> App - 点击搜索框中的相机 - 点击扫码”
  └── 百度资源可能显示“提取码：XXXX”

链接区
  ├── 资源标题（长标题可展开/收起）
  ├── 分享图标（复制分享）
  ├── 链接文本
  └── 操作：
       ├── 保存网盘（外链，target=_blank）

```

- 复制分享内容结构（脚本观察）：包含资源标题、分享链接、站点来源提示；具体文案不复刻。
- 证据：`Home.js` 中 `Fe()` 函数和弹窗模板。
- 注意：本站只借鉴“标题 + 链接 + 来源”的信息结构，文案由本站自行撰写。

## 4. 需求提交流程

### 4.1 页面加载

```text
打开 /demand
  -> 读取主题（localStorage）
  -> GET /api/notice（公告/说明文案）
  -> GET /api/demands、GET /api/demands/wanted（历史需求预加载）
  -> 默认显示“提交需求”Tab
```

- 证据：实际访问 `/demand`、`Demand.js` 初始化逻辑。
- 置信度：高。

### 4.2 提交需求

```text
填写：
  资源名称（必填）
  播放平台（必填，多选）
  播放地址（选填）
  备注说明（选填）
  联系方式（选填）
  是否愿意付费（选填）
点击“提交需求”
  -> 前端校验：
       资源名称为空 -> 提示“请输入资源名称”
       播放平台为空 -> 提示“请选择播放平台”
  -> POST /api/demand
       body: {
         title, platforms, play_url, remark, contact, is_paid
       }
  -> 成功：提示“需求已提交，我们会尽快处理！”
       清空表单
       重新加载历史需求
  -> 失败：显示服务端 message 或“提交失败”
  -> 网络异常：“网络错误，请稍后重试”
```

- 证据：`Demand.js` 中 `Z()` 提交函数；实际页面表单字段。
- 置信度：高（脚本 + 页面）；未实际提交，避免产生真实需求数据。

### 4.3 历史需求

```text
点击“历史需求 (N)”
  -> GET /api/demands
  -> GET /api/demands/wanted
  -> 列表渲染：
       排名（前 3 名高亮）
       标题
       状态徽章：已解决 / 待处理 / 已驳回
       日期/相对时间
       备注
       解决说明 / 驳回原因
       想要数
  -> 排序：
       按想要数
       按时间
  -> 点击“想要”：
       POST /api/demand/{id}/want
       -> 更新 want_count 和 userWanted
```

实测：
- 共 26 条需求；首条“奇妙萌可之魔法甜心，奇妙萌可之闪耀流星”，状态“已解决”，想要数 3。
- 证据：2026-10-19 实际访问 `/demand` 并切换到历史需求。
- 置信度：高（页面 + 脚本）；“想要”按钮未点击。

### 4.4 边界

- 空列表：显示“暂无需求记录”。
- 加载中：显示 spinner + “加载中...”。
- 提交中：按钮文案变为“提交中...”，禁用。
- 驳回原因：仅在已驳回状态展示。
- 解决说明：仅在已解决状态展示。

## 8. 对本站的实现建议（流程层）

1. **保留本站一次性请求/分页的稳定性，同时增加过程反馈**：先加计时器、结果数、进行中状态，再评估是否改为流式。
2. **筛选计数和排序放在前端完成**，后端只需提供稳定结果集和 `disk_counts`；避免为排序重复请求。
3. **资源弹窗或详情抽屉作为统一交付层**：保留直链/复制，增加二维码；不要改成扫码-only。
4. **需求板按“匿名提交 + 站长审核 + 想要投票 + 防刷”设计**，不要引入完整用户体系。
5. **移动端优先修复 tabbar 图标和横向筛选**，再做视觉细节。
6. **所有交互都用自己的文案和视觉实现**，不复用对方页面结构、样式或文案。
