# DuPanSou-Archive 改进实施计划

- 制定日期：2026-10-19
- 依据：本目录 `01`~`06` 文档、`docs/04-aliso公开页面对标与改进规划.md`、当前仓库代码
- 原则：
  1. 只借鉴功能与交互模式，不复用 aliso.vip 的代码、样式、文案、图片、接口；
  2. 优先增量改造现有 Flask + SQLite + Vue 3 结构，不重写；
  3. 先补搜索体验，再做运营型功能；
  4. 每项改动都要有可验证的验收标准和回滚方式。

## 1. 阶段划分

```text
阶段 0：基线与决策（0.5 天）
阶段 1：P0 搜索体验（1 周）
阶段 2：P1 数据与详情（2 周）
阶段 3：P2 运营型功能（按需）
阶段 4：回归、观测、迭代
```

---

## 2. 阶段 0：基线与决策

### 2.1 任务

| # | 任务 | 产出 |
|---|---|---|
| 0-1 | 确认搜索页目标：保留分页还是引入渐进式搜索 | 决策记录 |
| 0-2 | 确认 QR 库选型（轻量、无外部服务） | 依赖清单 |
| 0-3 | 确认排序语义：默认相关度不受影响 | 排序规则说明 |
| 0-4 | 确认网盘类型映射：光鸭、城通、ed2k 等 | `constants.js` 变更清单 |
| 0-5 | 确认法律页/公告的合规文案来源 | 文案清单 |
| 0-6 | 清理现有部署风险：`ACCEL_TOKEN` 硬编码 | 环境变量方案 |

### 2.2 决策建议

- **搜索**：第一阶段保留现有一次性请求 + 分页，只加耗时/状态/计数/排序；第二阶段再评估流式。
- **QR**：前端本地生成（如 `qrcode` 类库），不调用第三方二维码服务。
- **排序**：`relevance` 保持现有后端排序；`time`/`name` 只改变展示顺序，不改变有效性/存活降权。
- **网盘类型**：先补 `光鸭`、`城通`，再评估 `ed2k`/其他。
- **需求板**：默认暂缓，除非有明确运营计划。

## 3. 阶段 1：P0 搜索体验（1 周）

### 3.1 搜索状态条升级

**目标**：搜索完成后显示耗时、结果数、网盘类型数；搜索中显示进行中状态。

**后端**
- 文件：`backend/api/__init__.py`
- 在 `/api/search` 响应中增加：
  - `elapsed_ms`：服务端搜索耗时（可选，前端也可计时）
  - `disk_counts`：`{disk_type: count}`（见 3.2）
  - `total`：结果总数（已有则复用）
- 保持现有字段兼容，不删除旧字段。

**前端**
- 文件：`frontend/src/pages/ResourcePage.vue`
- 增加：
  - 搜索开始时间戳；
  - `elapsed` 计时器（搜索中每 250ms 更新，完成后停止）；
  - 状态文案：`搜索中…` / `已完成` / `已取消`（如后续支持取消）；
  - 结果数、网盘类型数、耗时。
- 保留现有实时/历史/检测/缓存信息，避免信息过载；窄屏下精简为数字 + 图标。

**验收**
- 搜索完成后 1 秒内显示耗时、结果数、类型数。
- 搜索失败时显示错误状态，不显示错误耗时。
- 刷新页面后状态不残留。

### 3.2 网盘筛选计数 + 多选

**目标**：每个网盘 chip 显示数量；支持多选和“全部”。

**后端**
- 文件：`backend/api/__init__.py`
- 在结果聚合完成后计算 `disk_counts`：
  - 基于当前结果集（未筛网盘前）统计；
  - 兼容 `disk_types` 多选；
  - 类型名称与前端 `constants.js` 对齐。
- 如果结果分页，`disk_counts` 应基于完整结果集，而不是当前页。

**前端**
- 文件：`frontend/src/pages/ResourcePage.vue`、`frontend/src/constants.js`
- 变更：
  - chip 文本：`夸克 (283)`；
  - `selectedDiskTypes: string[]`，空数组表示全部；
  - 多选切换；“全部”清空选择；
  - 移动端横向滚动 + 边缘渐隐；
  - URL 状态：`?disk=quark,baidu`（可选，但推荐）。
- 补类型：`光鸭`、`城通`；确认后端类型映射。

**验收**
- 计数与结果一致（抽样核对）。
- 多选后结果、计数、URL 状态正确。
- 移动端 390px 无横向溢出。
- 空结果时 chip 不显示或显示 0。

### 3.3 排序

**目标**：默认/时间/名称三种排序，状态写入 URL。

**后端**
- 文件：`backend/api/__init__.py`
- 增加 `sort` 参数：
  - `relevance`（默认）：保持现有相关度/存活/点击热度；
  - `time`：按时间降序；
  - `name`：按标题排序（本地化比较）。
- 分页时先排序再分页。

**前端**
- 文件：`frontend/src/pages/ResourcePage.vue`
- 增加原生 `<select>` 或自定义下拉；
- 状态写入 `?sort=time`，刷新/前进后退可恢复；
- 切换排序不重新请求（如果结果已完整返回）；若后端分页，则重新请求。

**验收**
- 三种排序结果符合预期。
- URL 可分享，刷新后保持。
- 默认排序与改动前一致（回归对比）。

### 3.4 同名变体编号

**目标**：把“同资源其他 N 个链接”展开行改为编号 chip/折叠面板。

**前端**
- 文件：`frontend/src/components/ResourceCard.vue`
- 变更：
  - 变体显示为 `1 2 3 … N` 编号；
  - 点击编号切换当前变体；
  - 显示每个变体的网盘、有效性、提取码（如有）；
  - 保留“打开/复制”操作。
- 如果变体很多，使用折叠面板，避免卡片过高。

**验收**
- 变体切换无需刷新。
- 当前变体高亮。
- 失效变体有明确标识。
- 移动端不溢出。

### 3.5 二维码补充交付

**目标**：卡片/弹窗增加“手机打开”二维码，保留直链和复制。

**前端**
- 新增组件：`frontend/src/components/ResourceQr.vue`（或类似）
- 文件：`frontend/src/components/ResourceCard.vue`
- 变更：
  - 点击“二维码”按钮打开小弹窗/抽屉；
  - 二维码内容为分享链接（含提取码提示，但不把敏感信息编码进二维码）；
  - 提示“使用手机相机或网盘 App 扫码”；
  - 保留“打开链接/复制链接/复制提取码”。

**验收**
- 二维码可被手机相机/网盘 App 识别。
- 直链、复制功能不回归。
- 二维码不包含 Cookie/账号/令牌。

### 3.6 移动端修复

**目标**：修复现有移动端细节，向 aliso 的移动体验看齐，但不照搬视觉。

**前端**

  - 确认移动端 tabbar 与路由高亮。

  - 资源卡隐藏次要信息（来源/URL），保留标题、网盘、有效性、操作。

**验收**

### 3.7 公告条 + 法律页入口

**目标**：增加可配置公告和页脚法律入口。

**后端**

## 4. 阶段 2：P1 数据与详情（2 周）

### 4.1 渐进式搜索

**目标**：边搜边出，显示已用时/已收到/持续搜索中，支持取消。

**方案 A（推荐，改动小）**
- 后端新增 `POST /api/search/stream`：
  - 并行调用 PanSou、本地索引、学霸盘等来源；
  - 每收到一个来源的结果就推送一行 NDJSON；
  - 最后推送汇总/结束标记；
  - 客户端断开时取消未完成的上游请求。
- 前端使用 `fetch` + `ReadableStream` 或 `EventSource`（取决于协议）；
- 维护：
  - `searching` 状态；
  - `elapsed` 计时；
  - `received` 计数；
  - `AbortController` 取消。

**方案 B（改动更小）**
- 保留一次性 `/api/search`，但后端先返回缓存/本地索引的快速结果，再返回实时结果（两次响应或轮询）。
- 前端先渲染快速结果，再合并实时结果。

**验收**
- 首条结果出现时间明显早于完整结果。
- 取消后不再追加结果。
- 网络错误有明确提示。
- 不破坏现有分页/缓存逻辑。

### 4.2 本地归档页面

**目标**：把已有 `/api/archive` 和本地索引变成可见功能。

**后端**
- 复用 `GET /api/archive`；
- 确认参数：关键词、网盘类型、仅存活、时间范围、分页。

**前端**
- 新增 `frontend/src/pages/ArchivePage.vue`；
- 路由：`/archive`；
- 导航入口：侧栏/移动端菜单/首页“📁本地”行；
- 搜索页增加“只搜本地”开关（对应 `only_archive`）。

**验收**
- 可按关键词/网盘/存活筛选。
- 分页正常。
- 与主搜索共享资源卡组件。
- 空态/加载态/错误态完整。

### 4.3 资源详情抽屉

**目标**：统一展示资源详情，而不是把信息堆在卡片里。

**前端**
- 新增 `frontend/src/components/ResourceDetailDrawer.vue`；
- 内容：
  - 标题、网盘、来源、时间、有效性；
  - 所有变体（编号/列表）；
  - 直链、提取码、复制、打开、二维码；
  - 失效举报；
  - 有效性历史（如果后端提供）。
- 卡片点击标题/详情按钮打开抽屉；保留卡片上的快捷操作。

**验收**
- 抽屉打开/关闭不影响搜索状态。
- 变体切换不刷新。
- 移动端全屏/底部抽屉适配。

### 4.4 批量有效性检测上屏

**目标**：让现有 checker 能力在搜索页可见。

**后端**
- 复用 `POST /api/check/batch`；
- 返回检测进度/结果。

**前端**
- 增加“检测本页链接”按钮；
- 显示检测中/完成/失败；
- 更新卡片有效性徽章；
- 保留“隐藏失效”开关。

**验收**
- 检测过程可取消/不阻塞页面。
- 检测结果与后端一致。
- 失败时有明确提示。

### 4.5 站点配置后台

**目标**：公告、首页词条、广告位、网盘开关可配置。

**后端**
- 复用现有配置/新增轻量配置表；
- 站长鉴权复用 `backend/access.py`；
- 配置读取公开、写入鉴权。

**前端**
- 在现有站长模式（如 `AccelPage.vue`）中增加“站点配置”区块；
- 或新增 `/admin/site` 页面（按现有路由习惯）。

**验收**
- 修改公告/词条后首页生效。
- 未授权用户不能写入。
- 配置变更可回滚。

## 5. 阶段 3：P2 运营型功能（按需）

### 5.1 需求板（可选）

**范围**
- 匿名提交；
- 站长审核/标记状态；
- 想要投票；
- 基础防刷（IP/频率/敏感词）；
- 历史需求公开列表。

**后端**
- 新表：`demands`、`demand_votes`；
- 接口：
  - `POST /api/demand`
  - `GET /api/demands`
  - `POST /api/demand/{id}/want`
  - 管理端审核/删除。
- 限流：复用现有 `rate-limit`/IP 黑名单能力（如果可用）。

**前端**
- 新页面 `/demand`；
- 表单/列表/状态徽章/想要按钮；
- 移动端适配。

**验收**
- 提交有校验和防刷。
- 审核状态正确。
- 想要投票幂等/可取消。
- 垃圾需求可被管理员删除。

### 5.2 多站点/工具导航（可选）

- 只有存在视频解析、少儿资源等衍生项目时再做。
- 采用“更多工具”菜单，不堆砌首页运营位。

### 5.3 网盘转存/保存（谨慎）

- 需要网盘账号、授权、合规评估；
- 不应默认开启；
- 不要把账号 Cookie/令牌暴露到前端；
- 与现有加速模块的账号体系隔离。

### 5.4 微信小程序/移动端承接（可选）

- 有明确移动产品规划再做；
- 否则响应式网页 + 二维码足够。

## 6. 测试与验收

### 6.1 功能回归

- 搜索：关键词、空关键词、特殊字符、长关键词、零结果、网络错误。
- 筛选：单选/多选/全部/无结果。
- 排序：三种排序 + 分页 + URL 状态。
- 变体：单变体/多变体/失效变体。
- 二维码：生成/识别/关闭。
- 移动端：390px、768px、1280px。
- 主题：亮/暗切换 + 刷新保持。
- 公告：显示/关闭/刷新不重复。
- 需求板（如做）：提交/审核/投票/防刷。

### 6.2 性能

- 搜索首条结果时间、完整结果时间；
- `disk_counts` 聚合耗时；
- 大结果集（500+）渲染性能；
- 移动端滚动/筛选流畅度。

### 6.3 可访问性

- 键盘可达：搜索框、筛选、排序、变体、弹窗关闭。
- aria-label：主题切换、二维码、关闭按钮。
- 对比度：亮/暗主题。
- 焦点管理：弹窗打开/关闭后焦点返回触发元素。

### 6.4 安全/合规

- 不复制对方代码/样式/文案/图片；
- 不调用对方接口；
- 二维码不含敏感信息；
- 需求板有防刷/审核；
- 公开部署前移除硬编码 `ACCEL_TOKEN`。

## 7. 回滚策略

| 改动 | 回滚方式 |
|---|---|
| `/api/search` 新增字段 | 字段向后兼容，前端可忽略；删除字段即可 |
| 筛选多选 | 保留单选开关/默认全部；出问题回退 UI |
| 排序 | 默认 `relevance`，关闭入口即可 |
| 二维码 | 独立组件，可隐藏入口 |
| 渐进式搜索 | 保留一次性 `/api/search` 作为回退；关闭流式开关 |
| 本地归档页 | 独立路由，可下线 |
| 需求板 | 独立路由/表，可停用 |
| 站点配置 | 默认值兜底；配置错误不影响搜索 |

## 9. 风险清单

| 风险 | 影响 | 缓解 |
|---|---|---|
| 流式搜索与 PanSou 上游不兼容 | P1 延期 | 先做后端多源并行/分块，不假设上游支持 SSE |
| `disk_counts` 在大结果集上变慢 | 搜索变慢 | 后端聚合、缓存、限制结果集 |
| 排序改变默认相关度 | 搜索质量下降 | `relevance` 保持原逻辑，新增排序独立 |
| 移动端改造引入回归 | 体验下降 | 390/768/1280 三档回归 |
| 需求板垃圾内容 | 运营负担 | 匿名 + 审核 + 防刷 + 敏感词 |
| 二维码被滥用 | 安全/合规 | 只编码分享链接，不含敏感信息 |
| 复制对方内容 | 法律风险 | 只借鉴功能思路，独立实现 |
| `ACCEL_TOKEN` 硬编码 | 密钥泄露 | 改为环境变量/本地配置，公开前轮换 |
