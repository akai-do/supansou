# aliso.vip 公开页面功能 / 交互对标与本站改进规划

- 采集日期：2026-10-19
- 采集范围：`https://aliso.vip/`、`/search?ai=<关键词>`、`/demand`、`safe.html / copyright.html / policy.html`，以及公开互链的 `hbh.aliso.vip`（视频在线解析）和 `zy.aliso.vip`（少儿动画资源库）
- 采集方式：只浏览公开渲染页面，覆盖桌面端 1280×720、移动端 390×844、亮色/夜间模式；**未登录、未抓取接口、未读取或复制对方代码**
- 用途：产品与交互对标，不构成法律意见。后续实现应基于自己的代码独立完成，不复刻对方页面代码、文案和视觉资产

---

## 0. 一句话结论

aliso.vip 的强项是**搜索过程可视化、结果聚合与移动端转化**：边搜边出数、网盘分类带数量、同名结果合并、扫码交付、需求板与微信小程序承接。

本站的强项是**链接可直接使用、有效性可验证、百度下载可加速**：直链 + 复制提取码、三态有效性检测与举报、本地历史索引、aria2/本机加速器、豆瓣榜单、统计页。

因此不建议照搬“扫码才给资源”和“一次渲染全部结果”，而应优先补齐：**搜索状态信息、网盘筛选数量与多选、排序、同名结果切换、移动端细节、二维码作为补充交付方式**。这些改动大多可以在现有前后端结构上增量完成。

## 3. 资源获取弹窗对标

aliso.vip 的网页端**不直接展示分享链接**，而是统一弹窗：

1. 标题：“请使用 XX App 扫码获取”
2. 说明：“打开 XX App · 点击搜索框中的相机 · 点击扫码”
3. 二维码
4. 百度网盘会额外显示“提取码：XXXX”
5. 资源标题（长标题可“展开”）+ 分享图标
6. 注意事项：
   - 资源 5 分钟后删除，请及时保存网盘
   - 链接由程序自动收集自公开网盘，不存储、不传播文件，跳转至网盘官网
   - 文件内容请自行辨别，仅供学习交流，无任何收费行为

本站当前是：**打开直链 + 复制链接 + 复制提取码 + 失效举报 + 同资源变体展开**。

**判断：** 本站的直链交付对桌面用户更友好，也是优势，不应改成扫码-only。建议增加“手机打开”二维码作为补充（由前端根据 URL 生成即可，无需后端），并在弹窗/卡片里保留直接打开和复制。扫码交付更适合移动端承接和 App 转化；是否要做取决于本站的移动端目标。

## 4. 需求板（/demand）对标

aliso.vip 有一个完整的“资源需求”板块：

- 两个 tab：**提交需求** / **历史需求 (26)**
- 提交表单：
  - 资源名称（必填）
  - 播放平台（必填，chips：爱奇艺、优酷、腾讯视频、芒果TV、B站、youtube、Disney+、其他）
  - 播放地址（选填）
  - 备注说明（选填）
  - 联系方式（选填：微信号/QQ/邮箱）
  - 是否愿意付费（选填：否/是）
- 文案：“想要人数超过 10，会加快寻找速度！”；“本站也提供有偿下载的服务，欢迎咨询！”
- 历史需求列表：
  - 共 N 条需求
  - 按想要数排序
  - 排名（前 3 名有颜色强调）
  - 标题、状态徽章（已解决 / 待处理 / 已驳回）
  - 日期、描述、解决说明、驳回原因
  - 爱心按钮 + 想要数

**本站现状：** 没有用户系统、没有求片/需求板、没有投票。

**建议：** 这是社区型功能，收益取决于运营投入。若要做，建议先做轻量版：匿名提交 + 站长后台审核/标记状态 + 想要投票 + 基础防刷；不要一开始就做完整用户体系。若没有持续运营精力，优先不做，避免产生大量无人处理的需求。

## 6. 生态与转化（aliso.vip 的做法）

- **视频在线解析**（`hbh.aliso.vip`）：抖音/快手/B站/微博等 78 个平台，登录/注册、解析记录、常见问题、免费额度、Windows 客户端、QQ 群/微信联系方式。
- **少儿动画资源库**（`zy.aliso.vip`）：首页、资源列表、精选合集、帆书检索；按年龄/语言/清晰度标注，包含最新、最热、标签、合集。
- **分享获益**：跳转到带 `invite_code` 的邀请注册链接。
- **微信小程序**：主站 banner 引导，强调“能看到资源目录结构”。
- **站长承接**：结果页底部“更多资源直接找站长”，带二维码。
- **法律页**：净网声明、版权说明、免责声明。

**本站现状：** 有 GitHub 入口、下载加速器、豆瓣榜单；没有多站点生态和转化承接。

**建议：** 如果本站只有单一产品，不必为了“像竞品”而增加大量运营位。可以优先做两件低风险的事：
1. 页脚补齐免责声明/版权/隐私入口；
2. 增加“反馈/求片/联系站长”入口（有需求板则指向需求板）。

## 7. 本站已有优势（不要为了对标而丢掉）

1. **直链可用性**：卡片直接展示 URL，可打开、复制链接、复制提取码；比扫码-only 更适合桌面和批量使用。
2. **有效性体系**：三态徽章（有效/疑似失效/已失效）、批量智能检测、用户举报、失效隐藏与降权、后台巡检。
3. **本地历史索引**：搜索结果实时入库、定时收割、零结果守望；这是 aliso 公开页面没有体现的能力。
4. **百度下载加速**：BDUSS/扫码、aria2、账号池、分段下载、带宽调度、本机 Hook 加速器；这是本站的差异化护城河。
5. **豆瓣榜单与海报**：11 类榜单、评分/年份排序、海报匹配。
6. **统计页**：索引总量、有效率、网盘分布、来源分布、热搜。
7. **工程细节**：分页/每页条数、缓存标记、来源与时间、纠错提示、封面图四级兜底。

对标时应以“补齐搜索体验”为主，不要削弱这些优势。

## 8. 改进项规划

**P0 验收标准：**
- 搜索完成后 1 秒内能看到耗时、结果数、网盘类型数；
- 网盘 chip 显示数量，多选后结果和数量正确联动；
- 排序切换后 URL 可分享，刷新后状态保持；
- 同名变体无需整页刷新即可切换；
- 390px 宽度下无横向溢出，tabbar 图标可见；
- 二维码可被手机相机/网盘 App 识别，直链和复制功能不回归。

## 9. 不建议照搬的点

1. **扫码-only 交付**：会伤害桌面用户体验和链接可复制性；本站应保留直链，二维码只作为补充。
2. **一次性渲染全部结果**：aliso 的长列表在结果多时对性能和可访问性不友好；本站分页是优势。
3. **公开他人搜索历史**：aliso 首页“历史”行看起来是全站历史；本站应坚持本机历史 + 聚合热搜。
4. **过度运营位**：小程序、邀请注册、站长二维码等会稀释搜索体验；按自己的运营能力取舍。
5. **复刻视觉/文案/代码**：只借鉴交互模式，独立实现；不要复制对方的页面结构、样式、图片和文案。
6. **抓取对方接口/数据**：本次对标没有做，后续也不建议做；数据来源应使用自己的 PanSou/插件/索引。

## 10. 建议的落地顺序

1. **第 1 周（P0）**：状态条耗时、网盘数量与多选、类型补齐、排序、变体切换、移动端修复、二维码。
2. **第 2 周（P1 前半）**：本地归档页面、统计页补全、公告/合规入口。
3. **第 3–4 周（P1 后半）**：渐进式搜索、加速能力上屏、结果聚合优化、索引 FTS5。
4. **之后（P2）**：根据运营数据决定是否做需求板、详情抽屉、多站点导航。

**衡量指标：**
- 搜索到点击/复制/打开的转化率；
- 筛选和排序的使用率；
- 零结果率、平均搜索耗时、首条结果出现时间；
- 失效举报率、有效链接占比；
- 移动端跳出率与 tabbar 使用率；
- 如做需求板：提交量、解决率、平均想要数、垃圾需求比例。
