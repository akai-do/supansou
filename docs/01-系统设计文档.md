# DuPanSou-Archive 系统设计文档

> 个人部署的网盘资源聚合搜索引擎 —— 融合"历史索引归档 + 实时聚合搜索"双通道。

---

## 0. 搜索质量优化记录（重要）

本项目的搜索体验曾明显逊于原生 PanSou，根因定位与修复如下：

| 问题 | 根因 | 修复 |
|------|------|------|
| **实时结果几乎为空** | PanSou 容器被误设 `AUTH_ENABLED=true` 但未配置用户，导致 `/api/search` 一律返回 `401 AUTH_TOKEN_MISSING`，实时通道完全失效 | 重建容器关闭认证（或正确配置用户）；`PansouClient` 增加可选自动登录 |
| **只搜到几十条 magnet** | 若用最小命令 `docker run ... pansou` 启动，PanSou 只监听默认 1 个 Telegram 频道，插件也未启用 | 通过 `CHANNELS` + `ENABLED_PLUGINS` 环境变量指定多频道与全部插件 |
| **历史/实时撞车重复** | 后端返回两分组，未跨源去重，同 URL 两条 | 新增 `_dedup_and_rank()`：以 URL 规范化去重，实时优先并补全历史已有密码 |
| **结果排序平庸** | 默认按时间，未结合相关度/存活/网盘偏好 | 综合评分 = 相关度 + 存活 + 密码完整 + 网盘偏好 + 时间 |
| **索引被超长文本污染** | `store_links` 未清洗标题，广告长文占满索引 | 只取标题首行并截断到 120 字符 |

优化后单次搜索实时通道可返回 **1000~3000 条**全类型结果（夸克/百度/阿里/迅雷/磁力等 10+ 种）；融合排序 + 同资源聚合分组后，以**分页**方式返回完整资源池（每页 10/20/50 张资源卡可选）。

## 一、项目背景

### 1.1 问题定义

网盘已成为国内用户分享和存储资源的主流方式。百度网盘、夸克网盘、阿里云盘、迅雷网盘等平台各自拥有海量资源，但存在以下问题：

- **信息分散**：用户需要在多个网盘搜索引擎间切换
- **实时性差**：传统网盘搜索引擎依赖爬虫建索引，新资源上传后数小时甚至数天才被收录
- **死链率高**：网盘分享链接经常失效，搜索结果中大量链接已无法访问
- **无个人记忆**：每次搜索都是"一次性"的，没有搜索历史回溯能力

### 1.2 项目定位

DuPanSou-Archive 是一个**个人部署的网盘资源聚合搜索引擎**，特色是"历史索引 + 实时搜索"双通道融合：

- **实时通道**：继承 PanSou 的实时聚合能力，快速获取最新资源
- **历史索引**：将每次搜索结果持久化到本地 SQLite 索引库，积累属于自己的资源索引

### 1.3 技术选型

| 组件 | 技术 | 理由 |
|------|------|------|
| 后端框架 | Python Flask | 轻量、易上手、文档丰富 |
| 搜索引擎基础设施 | PanSou (Go) | 成熟的实时聚合引擎，100+ 插件 |
| 索引存储 | SQLite | 零依赖嵌入式数据库，无需独立服务 |
| 前端框架 | Vue 3 + Vite | 现代响应式 SPA |
| 通信方式 | HTTP REST API | 前后端分离，部署灵活 |

## 三、创新点

### 3.1 双通道融合搜索算法

本项目最核心的创新。传统网盘搜索引擎要么只做实时聚合（如 PanSou），要么只做历史索引（如当年度盘搜）。本项目将两者结合：

```python
def search(keyword):
    # 通道1: 历史索引（搜老）
    archive_results = index_db.search(keyword)

    # 通道2: 实时搜索（搜新）
    realtime_results = pansou_client.search(keyword)

    # 融合策略：
    # - 实时结果同时写入索引（累积）
    # - 跨源去重 + 综合排序（相关度/存活/网盘偏好）
    #   → 同 URL 只保留一条，实时优先并补全历史已有密码
    #   → 前端合并为单一结果流展示（标记"实时/历史"来源）
    return merge(archive_results, realtime_results)
```

### 3.2 渐进式索引累积（替代传统爬虫）

当年度盘搜使用爬虫建索引，需要应付反爬、IP 封禁等复杂问题。本项目采用"搜索即索引"的渐进式策略：

- **每次用户搜索**：PanSou 的实时结果被存入 SQLite 索引库
- **定时收割**：后台线程用预设的热搜关键词列表，主动调用 PanSou 搜索并入库
- **结果**：使用时间越长，索引库越丰富，搜索体验越好

```python
# 搜索后的副作用：自动写索引
def search_handler(keyword):
    realtime = pansou_client.search(keyword)
    index_db.store_links(realtime)  # ← 一行代码实现索引积累
    return realtime
```

### 3.3 智能链接有效性检测

在早期"定时批量存活巡检 + 点击即时体检"的基础上，升级为**四级有效性状态机**：

```
检测源状态 (PanSou /api/check/links)         有效性 (link_index.validity)
  ok          ──────────────────────────────▶ ok       有效（排序 +0.5）
  bad         ─ 第 1 次 ────────────────────▶ suspect  疑似失效（降权 -2.5）
  bad         ─ 连续 DEAD_CONFIRM_STREAK 次 ─▶ dead     确认失效（-8 并隐藏）
  uncertain   ──────────────────────────────▶ suspect  疑似失效（不武断判死）
  unsupported ──────────────────────────────▶ ''       未检测（磁力/ed2k 永不降权）
```

设计要点：

- **防误杀（迟滞确认）**：检测源单次 `bad` 只降权不判死，连续 2 次失败才确认失效；
  确认失效后单次 `ok` 即恢复有效——假死比假活代价更高（死链还能靠举报兜底）。
- **新鲜度 TTL**：有效 72h、疑似 30min、失效 12h 内复用检测结果不重复送检，
  疑似尽快复检确认或洗白，失效定期复查探测分享恢复。
- **三个检测入口共用同一状态机**：周期巡检（1h/轮，疑似优先）、搜索后静默补检、
  前端当前页批量体检（`POST /api/check/batch`）、点击瞬间体检。
- **结果呈现**：搜索结果中失效降权、确认失效整卡隐藏（`hidden_dead` 随响应返回，
  前端可展开查看）；用户举报直接确认失效并撤销点击热度。
- **优先级巡检**：疑似失效 → 新入库未检测 → 失效复查 → 过期保鲜，磁力/ed2k 直接跳过。

### 3.4 零依赖一键部署

- 后端：Python + SQLite，安装 `pip install` 即可运行
- 前端：Vite 构建静态文件，由 Flask 直接 serve
- 无外部依赖：不需要 MySQL、Redis、Elasticsearch

## 四、技术难点与解决方案

### 4.1 搜索结果去重

**问题**：同一资源可能被多个 TG 频道和插件同时收录，导致结果重复。

**方案**：以 `url` 为唯一键做 SQLite UPSERT（`INSERT ... ON CONFLICT`），重复链接自动累加 `search_cnt`。

### 4.2 实时搜索超时处理

**问题**：PanSou 在某些插件或 TG 频道响应慢，可能导致请求卡死。

**方案**：设置 `PANSOU_TIMEOUT` 配置（默认 15s），超时后降级为"仅历史索引"模式，前端显示降级提示。

### 4.3 索引库膨胀

**问题**：长期使用后索引链接可能达到几十万条，查询变慢。

**方案**：
- SQLite WAL 模式提升并发读写性能
- 建立针对 title、url、disk_type、alive 等字段的索引
- `only_alive` 参数默认只搜索有效链接，减少无效数据

## 五、关键代码讲解

### 5.1 索引写入（indexer/database.py）

```python
INSERT INTO link_index (url, password, title, disk_type, ...)
VALUES (?, ?, ?, ?, ?)
ON CONFLICT(url) DO UPDATE SET
    last_seen = ?,
    search_cnt = search_cnt + 1,
    title = CASE WHEN ? != '' THEN ? ELSE title END
```

这是一条 UPSERT 语句——核心中的核心。新链接记录插入，已有链接更新 `last_seen` 并累加 `search_cnt`，实现"搜得越多，热度越高"。

### 5.2 双通道融合搜索（api/\_\_init\_\_.py）

```python
# 第1路：本地索引（毫秒级）
archive_results = index_db.search(keyword)

# 第2路：PanSou 实时搜索（秒级）
realtime_results = pansou_client.search(keyword)

# 实时结果写入索引（累积效应）
index_db.store_links(realtime_results)
```

这三步构成了整个项目的核心逻辑：先查本地、再查远程、远程结果自动入库。

### 5.3 定时收割（indexer/harvester.py）

```python
def _harvest_cycle(self):
    for keyword in self.keywords:
        links = self.search_func(keyword)  # 调 PanSou 搜索
        self.index_db.store_links(links)   # 收割入库
        time.sleep(2)                      # 频率限制
```

这是一个轻量级的"爬虫"替代方案——不爬网页，只搜已有的搜索引擎。每个关键词间隔 2s，避免触发频率限制。

## 六、部署指南

### 6.1 快速启动

方式一：docker compose 一键全栈（推荐，见仓库根 `docker-compose.yml`）：

```bash
docker compose up -d
# 打开 http://localhost:5000
```

方式二：手动启动：

```bash
# 1. 启动 PanSou 搜索引擎（Docker）
docker run -d --name pansou -p 8888:8888 \
  -e PORT=8888 -e AUTH_ENABLED=false \
  ghcr.io/fish2018/pansou:latest

# 2. 安装 Python 依赖
cd DuPanSou-Archive/backend
pip install -r requirements.txt

# 3. 启动 Web 服务 + 定时任务
python app.py

# 4. 打开浏览器
# http://localhost:5000
```

### 6.2 环境变量配置

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `PORT` | 5000 | Web 服务端口 |
| `HOST` | 127.0.0.1 | 监听地址；局域网/Docker 部署设为 0.0.0.0 |
| `DEBUG` | 0 | 调试模式开关（Werkzeug 调试器有 RCE 风险，勿对外开启） |
| `PANSOU_BASE_URL` | http://localhost:8888 | PanSou 地址 |
| `PANSOU_USERNAME` | (空) | PanSou 认证用户名（可选） |
| `PANSOU_PASSWORD` | (空) | PanSou 认证密码（可选） |
| `INDEX_DB_PATH` | ./data/index.db | 索引数据库路径 |
| `HARVEST_KEYWORDS` | 电影,电视剧,... | 定时收割关键词 |
| `HARVEST_INTERVAL_HOURS` | 6 | 收割周期（小时） |
| `CHECKER_INTERVAL_HOURS` | 1 | 智能巡检周期（小时） |
| `CHECKER_BATCH_SIZE` | 20 | 每批送检数量 |
| `CHECKER_CYCLE_LIMIT` | 300 | 每轮巡检最多检测条数 |
| `SMART_CHECK_ENABLED` | 1 | 智能有效性检测总开关 |
| `HIDE_DEAD_LINKS` | 1 | 搜索结果自动隐藏确认失效的资源卡 |
| `DEAD_CONFIRM_STREAK` | 2 | 连续失败多少次才确认失效 |
| `VALIDITY_OK_TTL_HOURS` | 72 | 有效结果保鲜期（小时） |
| `VALIDITY_SUSPECT_TTL_MINUTES` | 30 | 疑似失效复检间隔（分钟） |
| `VALIDITY_DEAD_TTL_HOURS` | 12 | 失效复查间隔（小时） |
| `SMART_CHECK_BACKGROUND_LIMIT` | 12 | 每次搜索后静默补检条数上限 |
